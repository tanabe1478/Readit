# UI操作の回帰テスト

UIの不具合は、まずユーザーの操作を自動テストで再現して失敗を確認し、そのテストを通す形で修正する。位置計算だけの単体テストで代用せず、可能な範囲で描画・ヒットテスト・入力イベントを通す。

## 実行

macOSでXcodeをインストールした環境から実行する。

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer cargo test --offline --bin readit ui_e2e_tests
```

既存のUIテストを含める場合は最後の `ui_e2e_tests` を省略する。依存が未取得の環境では初回だけ `--offline` を外す。

`src/ui_e2e_tests.rs` はGPUIのテスト用ウィンドウ上で、実際のReader、エディタ、吹き出しを描画する。テスト用ソースとガイドの初期登録後、操作はプラットフォーム入力イベントとして投入する。位置の検証には描画された要素のboundsを使い、位置計算関数の戻り値やドラッグ状態の直接書き換えは使わない。

これはアプリ内のUI操作を端から端まで通すテストで、配布された `.app` の起動・macOSのウィンドウ管理・GPU描画を検証するOSレベルのE2Eではない。これらに関わる不具合では、配布ビルドを使った実画面の操作確認も行う。

## スクロール後に吹き出しを下へ動かせない

`guide_scroll_then_drag_to_bottom_e2e` の操作と検証：

1. 160行のソースを開き、40〜42行に短い説明を表示する。
2. まずコードをスクロールし、自動配置の吹き出しが移動することを確認する。次に描画されたタイトルの位置を取得し、吹き出しを上部へドラッグして、実際に指定位置へ移動したことを確認する。
3. コード上へホイール入力を送り、表示行が変わったことを確認する。
4. 手で配置した吹き出しの位置が維持されることを確認する。
5. タイトルを再取得し、吹き出しを画面下部へドラッグする。
6. 実際の描画位置が要求位置に一致し、画面内に収まることを確認する。
7. コード選択、未保存状態、ディスク上のソースが変わっていないことを確認する。

2026-09-12に旧高さ計算だけを一時的に復元して検証した。実際の吹き出しは高さ160.5pxだったが、800pxの最大高さで移動を制限する旧計算では、要求Y=809.5pxに対して描画Y=188pxとなり、手順6で失敗した。実測の高さを使う修正版では通過した。この検証は旧バイナリ全体の再実行ではなく、不具合の原因となった計算を戻した回帰検出の確認である。

## 実アプリでの再現完了：スクロール後の下方向ドラッグ

その後、作業履歴の2026-09-12 20:56の変更直前に取得したソース出力から、吹き出しの表示処理とドラッグ開始処理を復元してリリースビルドを作成した。保存されていた古いバイナリとは別に、この **修正直前の処理を復元した実アプリ** で報告と同じ移動制限を再現できた。報告時の実行ファイルそのものの再利用ではない。

再現用ソースはPiの `agent-loop.ts` のコピー。306〜310行に報告と同じ説明を表示し、以下をネイティブウィンドウ上で実施した。

1. 吹き出しをタイトルから右下へドラッグする。
2. エディタを上へスクロールし、306行が画面の下側へ移る状態にする。
3. 吹き出しをタイトルから画面上部へ動かし、上方向には移動できることを確認する。
4. 同じタイトルを下方向へドラッグする。旧版は途中で止まり、修正版は要求した下部へ届く。

1171×768の取得画像では、手順4でタイトルを `(837, 90)` から `(837, 550)` へドラッグした。旧版の吹き出し上端は約181pxで停止したが、修正版では約534pxに移動した。旧版の入力ログでも左ボタンを押したまま下へ動くイベントを確認した。診断版には入力ログだけを追加し、配置とイベント処理の振る舞いは変更していない。
