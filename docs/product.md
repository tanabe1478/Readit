# Readitの製品方針

AIが書いたコードを、人間が根拠を辿って理解できるようにする。VSCodeやZedと同様のファイルツリー、タブ、本文、編集操作を基本とする。

## エディターとAIの役割

エディターはコードと、その定義・使用箇所・差分を正確に表示する。ガイド中はコードに紐づく一時的な吹き出しを表示する。説明の生成はユーザーが利用しているAIクライアントが担当する。メモはユーザーの好みのツールで管理する。

AIはMCPを通して、人間が見ているReaditの表示を操作する。skillには、その操作を使ってコードの読み方を案内する方法を記述する。AIプロバイダーや特定の会話UIに依存させない。

たとえば入口の関数を表示し、入力型の定義へ移動し、条件分岐を選択し、呼び出し元と境界条件のテストを順に示す。説明と根拠のコードが一致することを重視する。人間が途中で別の場所へ移動した場合は、古い案内を止め、再開の意図を確認する。

## UI

- 左: 通常のファイルツリー。フォルダ操作、検索、ファイルへのアクセス。
- 中央: タブと編集可能な本文。構文ハイライト、選択、定義ホバー、ジャンプ、移動履歴。
- 下: 必要なときに定義・使用箇所などの結果を表示。

独自の読む順番を通常のファイルツリーと置き換えない。現在の読む順番表示はファイル名ヒューリスティックによる仮案内であり、依存グラフの解析結果ではない。

## 外部操作の初期実装

状態の取得、ファイル一覧、未保存本文の取得、文字列検索、ファイルと行・範囲の表示、LSPによる定義・参照等の解析、移動履歴、差分・折返し・ツリーの切替をMCPで提供する。

画面を操作する要求は対象workspaceを明示する。編集中の本文を勝手に保存せず、保存確認などのダイアログも外部操作で閉じない。LSP結果は取得時の本文と対応させ、人間の移動や編集によって古くなった結果で画面を動かさない。

実装と接続方法は [MCP](mcp.md)、案内方法は [readit-guide](../skills/readit-guide/SKILL.md)にまとめる。

## 編集して理解する

書く機能は維持する。条件や入力を変更し、結果を観察することで理解が深まる場合がある。通常の編集、Undo/Redo、保存、差分を使えるようにする。
MCPの初期版は閲覧とナビゲーションを対象とし、ソースの書換え・保存・シェル実行APIは含めない。編集や実行の自動化を追加する場合も、読解の案内と区別してユーザーが目的を選べる形にする。

## 今後の優先順位

1. MCPで表現できる通常操作を増やす。エディター分割、呼び出し階層、比較範囲など。
2. 大規模リポジトリの読み込み、ファイル監視、LSPの診断・補完、クラッシュ復旧。
3. 更新、署名・notarization、依存ライセンス一式、商用配布。

コードを理解できたかは、目的・影響範囲を説明できるか、境界条件の挙動を予測できるかで評価する。メモの数や説明文の長さを評価基準にしない。
アプリ本体を非公開で商用販売できる構成は維持する。試作段階のリポジトリ公開はユーザーの方針に従う。
